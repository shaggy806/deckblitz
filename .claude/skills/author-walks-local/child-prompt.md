Run the `SKILL` skill (/SKILL) for one batch, as WALK. Your range is **RANGE**. This batch is BATCH_SETS. HOW_TO_PICK

This is one of several card-authoring sessions running in parallel **on this one PC**, each in its own git worktree and owning its own range of sets so none walks another's (BACKLOG.md's line for the author-by-set skill records the ranges). Stay strictly inside your range: if `cards:sets` offers a card from a set outside it, skip that card.

- **Set up your worktree first** (it has no `node_modules` or `dist/`): `git fetch origin main && git merge origin/main`, then `npm install --no-save --no-audit --no-fund` (your own copy — never a junction to another checkout's), then `node scripts/typecheck-turn.mjs npm run build -w engine`.
- **Your agents' `MAIN_CHECKOUT` is this worktree's path** (`git rev-parse --show-toplevel`), so their `node_modules` junctions point at your copy, never the repo's main checkout. Use **at most four `card-author` agents** (groups of ~18–25): three sessions share the machine.
- **The machine is shared.** Every build, typecheck and `card:scaffold` of yours goes through `node scripts/typecheck-turn.mjs <command>` for the whole batch, not only while your agents run: the other sessions' agents are typechecking too. `npm run verify` takes the whole machine by itself and waits for the other sessions' verifies ("another verify on this machine has it" is normal — run it in the background and wait on its notification). Never wrap a verify in `typecheck-turn.mjs`.
- Your batch number is **BATCHNUM** (`engine/data/sweep-3/BATCHNUM.json`). Before landing, `git fetch origin main` and check no other walk took it; if one did, use the highest number on `origin/main` plus one and rename your record (and its references).
- Verifying, as `agent-batches.md`'s Integrating step 4 says, **on your own branch, before the lock**: `npm run verify -- --fuzz-new` in the background as soon as the batch is committed while you write the record and docs; then `git fetch origin main && git merge origin/main` and the one plain `npm run verify` (it picks full or quick itself; commit `scripts/verify-state.json` if it rewrites it). After a fix, `npm run verify -- --only <step>`. A fuzzer timeout's line says where the game was: don't replay it at a longer `--timeout`.
- Landing, **one session at a time, under the landing lock** (`scripts/landing-lock.mjs`). Don't push your session branch: it stays on this PC, and only `main` matters. Once that verify is green and the record and docs are committed, run `node scripts/landing-lock.mjs acquire BATCHNUM --wait` in the background; it exits 0 when you hold the lock. Holding it: `git fetch origin main && git merge origin/main`; if the merge brought anything, `npm run verify -- --landing` and commit what it regenerates; then `git push origin HEAD:main` and `node scripts/landing-lock.mjs release`. **Always release**, also when a check fails: release, fix, then acquire again. Merge conflicts: in the generated card files (`engine/src/cards/generated*.ts`, `shards/`) take either side and re-run `npm run gen:cards -w engine`; in `BACKLOG.md`, `COMPLETED.md`, `docs/card-blockers.md` or `engine/data/needs-vocabulary.json` keep both sides' entries; in `scripts/verify-state.json` the side with the higher `lastFullBatch` (with its `lastFullCommit`). Keep `engine/src/game.ts` CRLF through any resolution. If the push is still rejected, merge once more, run the same `--landing` check and push again before releasing.
- If the batch needs a new engine feature, first check `git log origin/main` for the same feature landing from another session; build it only if none did.
- One batch, then stop: update your walk's hand-off in BACKLOG.md (the next sets in *your* range), land it, remove your agents' worktrees (`agent-batches.md` Integrating step 5 — unlink each junction first; `git worktree list` lists the other sessions' worktrees too: touch only yours), and finish with a short report: cards authored and blocked, any feature built, the commit on `main`, and how long you waited on the machine gate (typecheck turns and the verify queue).
